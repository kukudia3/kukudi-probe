通知（Telegram）

配好之后，节点离线 / 恢复 / 流量超限 / 到期，以及下面三个定时流量报告都会推送。没配 Telegram 时它们仍会写进服务端日志。

Telegram 推送

留空表示不修改已保存的 Token。

私聊/群组填数字 ID，频道填 @用户名。

定时流量报告

按服务端时区在 09:00 发送，内容是上一个完整周期里每台机器的上传 / 下载 / 总计，末尾一行合计。没配 Telegram 时它们同样只写进服务端日志。

告警参数

时间写法如 30m / 60s / 1h30m；留空表示用服务端默认值。改完立刻生效，不需要重启。

判定与提醒节奏

节点持续异常时，同一条告警最短隔多久再提醒一次。填 0 会约每秒提醒一次，别填 0。

服务端启动后这段时间内不发通知；判定照常进行，只是不发出。改动这个值并保存时，静默期从保存那一刻重新计时。

节点已经判离线后，再连续离线这么久才发告警。判离线本身的阈值是服务端参数（见「服务器信息」）。

恢复在线后要连续稳定这么久才发「已恢复」；先前没报过离线告警则不发。

    允许访客查看（只读）

    默认关闭。关着的时候，未登录的人只能看到登录页（与以前完全一样）。改完立刻生效，不需要重启。

    打开之后，任何能访问到这个地址的人都能看到：节点名称与在线状态、CPU / 内存 / 硬盘 / 负载、网络速率与流量、延迟曲线与丢包、内核与系统版本、磁盘挂载路径、分组与地区、计费周期与到期日，以及价格 / 月均 / 剩余价值。首页每秒的实时推送与上面这些走的是同一份脱敏逻辑。

    访客看不到：本机地址与来源 IP、探测目标的地址、备注、操作记录（审计），以及全部设置项（含 Telegram Bot Token、Chat ID、汇率来源）。所有写操作（新增 / 修改 / 删除节点、改设置）都仍然需要登录，与这个开关无关。

    脱敏在服务端完成：这些字段在访客的响应里根本不存在（不是前端藏起来）。如果你的面板在公网上，建议同时确认登录接口的限流与反代的访问控制。
